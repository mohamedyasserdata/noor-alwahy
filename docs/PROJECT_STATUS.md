## 4. قيود البيئة والعوائق المعروفة

- Docker Desktop 4.95.0 ومحرك 29.8.2 يعملان؛ تثبيت المستخدم موجود خارج `PATH` القديم لجلسة
  Codex، لذلك تستعمل أوامر الجلسة مساره الكامل. الطرفية الجديدة بعد إعادة الفتح يفترض أن تلتقطه.
- Supabase CLI 2.121.0 مثبت كاعتماد تطوير، والحزمة المحلية تعمل حاليًا.
- لم يُنفذ workflow على GitHub بعد لأن المستودع محلي، لكن جميع أوامره المكافئة شُغّلت محليًا
  بنجاح؛ أول push أو pull request هو التحقق المستضاف الأول.
- `pnpm peers check` يحذر لأن بعض إضافات ESLint تعلن دعمًا حتى ESLint 9 فقط. وثائق Next.js
  16.4 تنص على دعم ESLint 10 واحتمال هذه التحذيرات؛ `pnpm lint` الفعلي ناجح.
- محمّل `@tailwindcss/turbopack` الذي ولّده create-next-app انهار على Windows. استُبدل
  بتكامل `@tailwindcss/postcss` الرسمي، وبعده نجح بناء الإنتاج.
- لا نشر حاليًا: حُسم G-24 في ADR-004 لصالح Vercel + Supabase مستضاف، لكن اختبار staging والنشر
  الفعليان مؤجلان إلى P11-T05.
- تستورد next-intl مترجم SWC في الإعداد. فُرض `@swc/core@1.15.33` مؤقتًا بسبب عطل
  native binding موثق في 1.16.x على Windows؛ شروط إزالة القيد موثقة في ADR-001.
- ظهر عارض متقطع في عامل PostCSS/Turbopack مع cache `.next` على Windows؛ البناء النهائي
  نجح بعد إيقاف التوازي وتنظيف الكاش. لا تغيير كود مطلوب ما لم يصبح العارض متكررًا.
