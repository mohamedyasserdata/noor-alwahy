# ADR-004: محرك PDF العربي والاستضافة

- **الحالة:** مقبول
- **التاريخ:** 2026-10-17
- **المهمة:** P0-T06

## السياق

تحتاج الشهادات والتقارير والإيصالات وكشوف الأجور إلى عربية وRTL وتشكيل وخطوط مضمّنة وQR
ونص قابل للبحث. قارنت المهمة محرك Chromium عبر HTML/CSS مع `@react-pdf/renderer` على شهادة
A4 أفقية واحدة بالمحتوى نفسه. استوردت الآيات الثلاث آليًا من Tanzil Uthmani 1.1 بعد مطابقة
بصمة الملف الكامل وعدد 6236 آية؛ لم يُكتب نص قرآني يدويًا.

## نتيجة الـSpike

| الفحص                                      | Chromium | React-PDF  |
| ------------------------------------------ | -------- | ---------- |
| اتصال الحروف واتجاه RTL والتشكيل بصريًا    | ناجح     | ناجح       |
| اسم عربي طويل بلا قص أو كسر                | ناجح     | ناجح       |
| مزج العربية مع أرقام غربية ومعرّف لاتيني   | ناجح     | ناجح       |
| A4 أفقي، صفحة واحدة                        | ناجح     | ناجح       |
| جميع الخطوط المستخدمة مضمّنة               | ناجح     | ناجح       |
| الاسم ومرجع السورة قابلان للاستخراج والبحث | ناجح     | ناجح       |
| QR بعد تصيير الصفحة إلى PNG بدقة 180 DPI   | ناجح     | ناجح       |
| الحجم أقل من 1MB                           | 148,566B | 37,163B    |
| PDF معلّم `tagged`                         | نعم      | لا         |
| المقارنة بمرجع بصري معتمد                  | 0% فرق   | غير مطلوبة |

المراجعة البصرية الموثقة تحققت من عدم وجود تداخل أو قص أو مربعات سوداء، ووضوح التشكيل
والبيانات والـQR. أعيد التوليد بعد اعتماد مرجع Chromium، وبقي فرق البكسلات 0 ضمن سماحية 0.1%.

## القرار

1. **Chromium عبر HTML/CSS هو محرك الإنتاج الأساسي.** يستخدم لاحقًا `puppeteer-core` في
   Route/عامل خادمي، مع HTML مملوك للمشروع ومدخلات متحققة؛ لا يُقبل HTML خام من المستخدم.
2. `@react-pdf/renderer` ليس محرك الإنتاج، لكنه يبقى اعتماد تطوير لإعادة إنتاج المقارنة. نجح
   بعد فصل مقاطع الخط العربي/اللاتيني، وتعطيل التفاف الصفحة، والالتزام بمجموعة تنسيق أضيق؛
   وهذه قيود صيانة لا يحتاجها Chromium.
3. خطوط Cairo وAmiri المحلية هي المصدر الوحيد للخطوط في PDF، ولا تحميل خطوط من CDN أثناء
   التوليد.
4. نص القرآن في الإنتاج يأتي من جداول المصحف الموثقة فقط. fixture الحالية مشتقة آليًا من
   Tanzil ومخصصة للـSpike والاختبار.

## قرار الاستضافة

الخيار المعتمد هو **Vercel للتطبيق + Supabase المستضاف**. عند تنفيذ أول Route PDF يُستخدم
`puppeteer-core` مع `@sparticuz/chromium-min` وفق نمط Vercel الرسمي، ولا تُضمّن حزمة Playwright
أو Chromium الكاملة في Function. إذا تجاوزت وظيفة PDF حد الحزمة أو الذاكرة في اختبار staging،
يُنقل التوليد فقط إلى خدمة حاوية صغيرة؛ لا يتغير محرك القوالب ولا يُعاد فتح قرار React-PDF.

هذا قرار توافق معماري، وليس إثبات نشر: اختبار staging الفعلي مؤجل إلى P11-T05.

## التحقق القابل لإعادة الإنتاج

```bash
pnpm pdf:spike:fixture
pnpm pdf:spike:generate
pnpm pdf:spike:verify
```

يتطلب الفحص Poppler (`pdfinfo`, `pdftoppm`, `pdftotext`) وPython مع `pypdf`. تحفظ PDF النهائية
في `output/pdf/` وتحفظ لقطة Chromium المعتمدة في
`tests/fixtures/pdf/baselines/certificate-chromium.png`.
