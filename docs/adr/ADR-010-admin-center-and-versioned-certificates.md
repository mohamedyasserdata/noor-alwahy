# ADR-010: مركز إدارة حتمي وشهادات ذات نسخ ثابتة

- **الحالة:** مقبول
- **التاريخ:** 2026-10-20
- **القرار:** اعتماد المالك لتعديل P8-T03 واستبدال P10

## السياق

كانت المرحلة 10 تخطط لعميل Anthropic ومساعد مدير وتوليد مسودات. اعتمد المالك إلغاء كل
ميزات الذكاء الاصطناعي ومزودي النماذج، واستبدالها بمركز إدارة ومتابعة يعتمد بيانات قابلة
للمراجعة. كما توسع نطاق P8-T03 من قالب شهادة مبسط إلى مكتبة احترافية، بشرط ألا تتغير
الشهادات الصادرة عند تعديل قالبها وأن يبقى توليد PDF مناسبًا لموارد Hostinger.

يتعارض القرار الأول مع AI-01…06 والمادة 7 القديمة وP10 القديمة؛ لذلك هذا ADR **يستبدلها**
ولا يتركها كمسار اختياري. لا يتغير أي نطاق أساسي آخر.

## القرار

1. يمنع كود المنتج من أي SDK أو API أو مفتاح أو Route أو مخزن متجهات خاص بنماذج AI. تُحذف
   متغيرات Anthropic، ويضاف فحص يمنع عودة التكامل عند P10-T05.
2. تتحول P10، مع إبقاء أرقام T01…T05 وعدد المهام، إلى: مؤشرات موحدة، قواعد وحالات تدخل،
   تقارير وتصدير، واجهة «يحتاج تدخلك» وتنبيهات، وقوالب حتمية ذات نسخ.
3. المؤشرات والقواعد لا تعيد تنفيذ منطق الأعمال: تستخدم Views/RPCs والدفاتر والدوال التي
   تملكها مراحل الحضور والحفظ والدرجات والاشتراكات والمال. كل نتيجة تحمل سببًا وأدلة قابلة
   للمطابقة، وتظل العملات منفصلة.
4. كل إعداد عتبة أو انتقال حالة أو نشر قالب أو تصدير حساس للمدير ذي AAL2، تحت RLS وتدقيق.
   الوظائف المجدولة والتصدير idempotent، والروابط الخاصة قصيرة العمر.
5. قالب الشهادة كيان منطقي وله نسخ منشورة immutable. الشهادة تشير إلى نسخة محددة وتحفظ
   `payload_snapshot` و`template_snapshot` وhash للملف؛ لا يعاد تفسيرها بقالب حالي.
6. محرر الشهادة schema منضبط ومتغيراته allowlist؛ لا HTML/CSS تنفيذي ولا سحب حر. يدعم
   الهوية الإسلامية والشعار والختم والتوقيعات والمعاينة واللغتين داخل مناطق آمنة للطباعة.
7. الإصدار الجماعي queue محدود التوازي (1 افتراضيًا) مع idempotency وإعادة محاولة العناصر
   الفاشلة فقط. يبقى Chromium/HTML من ADR-004، بأصول وخطوط محلية وإعادة استخدام المتصفح.
8. QR يحمل رابط تحقق HTTPS برمز عشوائي فريد ولا يحمل PII. الإلغاء يضيف حالة وسببًا وتدقيقًا؛
   لا يحذف الملف ولا يعيد استخدام الرقم أو الرمز.

## التوافق والأداء

- لا تبعية جديدة لازمة للتوثيق؛ التنفيذ يستخدم Chromium و`qrcode` و`exceljs` المعتمدة.
- عند P8-T03 يقاس batch على بيئة مماثلة لخطة Hostinger الفعلية. إن فشلت الحدود، ينقل عامل
  PDF فقط إلى خدمة حاوية، مع بقاء renderer والعقد واللقطات نفسها.
- تلزم فهارس للفترة والحالة والمفاتيح الأجنبية و`dedupe_key`، وترقيم/تجميع خادمي؛ لا تحميل
  بيانات خام كاملة إلى المتصفح.

## معايير إثبات القرار

- pgTAP لقيود النسخ والثبات وRLS وdedupe والانتقالات؛ وVitest للـrenderers والقواعد.
- E2E كامل للإصدار الفردي والجماعي والتحقق والإلغاء، ولمركز التدخل والتصدير.
- فحص PDF آلي وبصري لكل فئة قالب، ومسح QR، واستخراج النص، وتضمين الخطوط والأبعاد والحجم.
- استعلام مرجعي يطابق كل KPI وتقرير، واختبار سباق وإعادة محاولة للوظائف.
- بحث CI يثبت غياب تكاملات AI ومفاتيحها ومساراتها من المنتج.
