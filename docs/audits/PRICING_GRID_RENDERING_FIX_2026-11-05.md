# تقرير إصلاح عرض شبكة الأسعار

التاريخ: 5 نوفمبر 2026

## ملخص المشكلة

كانت صفحة شبكة الأسعار الإدارية تستدعي `connection()` داخل `getPricingGridData`، بينما لم تكن الصفحة تعلن صراحةً أنها صفحة ديناميكية. لذلك حاول Next.js إدخالها في مسار التحسين المسبق، ثم سجّل تحذيرًا/تشخيصًا لأن البيانات تعتمد على اتصال المستخدم وقاعدة البيانات وقت فتح الصفحة.

المشكلة ليست في جدول الأسعار أو بياناته، ولا تتطلب Migration أو تغييرًا في قاعدة البيانات.

## الحل المنفذ

أضيف `export const instant = false` إلى صفحة:

`app/[locale]/(admin)/admin/packages/pricing-grid/page.tsx`

هذا هو النمط المستخدم بالفعل في صفحات البوابات الديناميكية داخل المشروع. نتيجته أن Next.js لا يحاول تجهيز الصفحة كصفحة ثابتة، بل ينفذ استعلاماتها وقت طلب المدير لها.

## لماذا هذا هو الحل الأنسب؟

- بيانات الأسعار إدارية ومتغيرة وتعتمد على جلسة مستخدم، لذلك العرض الديناميكي هو السلوك الصحيح.
- يحافظ على استعلامات `Promise.all` الحالية؛ أي تظل الباقات والدول والأسعار والاشتراكات تُجلب بالتوازي بدل إنشاء waterfall.
- لا يعطل الكاش العام للموقع، ولا يحول المشروع كله إلى عرض ديناميكي؛ التأثير محصور في صفحة شبكة الأسعار فقط.
- لا يكرر البيانات ولا ينشئ API أو نظام أسعار موازٍ.
- لا يحتاج تعديلًا في قاعدة البيانات أو RLS.

## ما لم يتم تغييره

- لم تتغير أسعار أو عملات أو باقات.
- لم يتغير منطق المعاينة أو النسخ الجماعي للأسعار.
- لم تتغير صلاحيات المدير.
- لم تتغير صفحات الباقات العامة.

## تحسينات مستقبلية غير مطلوبة الآن

إذا أصبحت شبكة الأسعار ضخمة جدًا لاحقًا، يمكن إضافة pagination للدول أو تحميل خلايا السعر عند فتحها. لا أنصح بتنفيذ ذلك الآن لأن الحل الحالي أبسط، صحيح، ويحافظ على تجربة المدير دون تعقيد إضافي.
