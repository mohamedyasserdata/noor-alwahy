# P11-T01 — مراجعة الأمان

## النطاق

تغطي هذه المراجعة سياسات RLS، ودوال `security definer`، وSupabase Storage، وحدود المعدل،
ومفاتيح الخدمة، ورؤوس HTTP/CSP، وتبعيات الإنتاج. المرجع الملزم هو دستور المشروع، ولا تعتمد
أي صلاحية على إخفاء عناصر الواجهة.

## نتائج المراجعة الساكنة

| السطح              | النتيجة                                                                                | الضابط                                      |
| ------------------ | -------------------------------------------------------------------------------------- | ------------------------------------------- |
| جداول `public`     | لكل جدول منشأ عقد RLS ساكن                                                             | `pnpm check:security` + اختبار pgTAP المؤجل |
| `security definer` | لا تعريف بلا `set search_path` ثابت                                                    | فحص كل تعريف في المهاجرات                   |
| مفتاح الخدمة       | محصور في `lib/supabase/admin.ts` المحمي بـ`server-only`                                | فشل CI عند ظهوره في مسار منتج آخر           |
| Storage            | الحاويات المعرفة خاصة؛ أصول الشهادات للمدير، والتصدير لصاحب الطلب الإداري الساري       | سياسات `storage.objects` + RLS              |
| الطلبات العامة     | reCAPTCHA، حد جسم 32KB، Zod، HMAC للمعرفات، وحد IP/contact ذري                         | `submit_application`                        |
| التحقق من الشهادات | نتيجة محدودة، لا قراءة صف مباشرة، وحد 15 محاولة/10 دقائق                               | `verify_certificate`                        |
| HTTP               | CSP، منع الإطارات وMIME sniffing، سياسة صلاحيات، referrer، COOP/CORP، وHSTS في الإنتاج | `next.config.ts`                            |
| التبعيات           | إصدارات مثبتة، لا ثغرات معروفة في الإنتاج، وفحص high severity في CI                    | `pnpm audit --prod` + Dependabot            |

## قرار CSP

لم يُستخدم nonce لأن نسخة التطبيق تعتمد PPR وISR، ودليل Next.js المثبت يقرر أن nonce يجبر
الرندر الديناميكي ويعطل PPR والتخزين الطرفي. لذلك استُخدمت سياسة ثابتة تسمح بـinline اللازم
لـNext.js وJSON-LD، وتحصر الاتصالات في الأصل وSupabase المعرّف وreCAPTCHA. لا تسمح السياسة
بـobjects أو framing أو form actions خارج الأصل، وتضيف `upgrade-insecure-requests` وHSTS في
الإنتاج فقط حتى لا تكسر التطوير المحلي.

## الإغلاق النهائي في 2026-10-24

- أعيدت قاعدة Supabase من الصفر ونجحت 53 ملفات pgTAP بعدد 1403/1403، ثم RLS ‏2/2 وSQL
  lint على `public` و`private` بلا أخطاء.
- نجح فحص رؤوس نسخة production المحلية فعليًا، ومنها CSP وHSTS وDENY وnosniff وCOOP/CORP
  وPermissions-Policy، واستجاب health check بقاعدة reachable دون كشف بيانات.
- نُفذت المراجعة عبر الجهازين: نفذ الجهاز الثاني الضوابط وراجعها، ثم أعاد الجهاز الأول البوابات
  الأمنية المستقلة بعد الدمج.
- فحص Gitleaks ‏v8.30.1 كل تاريخ Git (175 commit، نحو 6.94MB) ولم يجد تسريبًا.

بذلك أُغلقت P11-T01. لا يغير هذا ضرورة استمرار Dependabot وCI عند كل تغيير لاحق.

## نتائج التنفيذ في 2026-10-23

- نجح `check-security-static`: ‏74 جدولًا عامًا، 65 مهاجرة، و276 ملف منتج.
- نجح `pnpm audit --prod --audit-level high`: لا توجد ثغرات معروفة.
- لم تُشغّل اختبارات قاعدة البيانات أو RLS أو E2E أو build.

هذه النتائج القديمة superseded بنتائج الإغلاق أعلاه ولا تمثل الحالة الحالية.
