## 3. طريقة التشغيل مع أي نموذج

### أ) مع GitHub Spec Kit
```bash
uvx --from git+https://github.com/github/spec-kit.git specify init noor-alwahy --ai claude   # أو copilot/gemini/cursor...
# ثم انسخ الملفات إلى .specify/ و specs/001-noor-alwahy/ كما يلي:
#   00-constitution.md -> .specify/memory/constitution.md
#   01-spec.md         -> specs/001-noor-alwahy/spec.md
#   02-plan.md         -> specs/001-noor-alwahy/plan.md
#   03-data-model.md   -> specs/001-noor-alwahy/data-model.md
#   04-tasks.md        -> specs/001-noor-alwahy/tasks.md
# ثم نفّذ داخل الوكيل:  /speckit.implement  (مرحلة واحدة كل مرة)
```
> أوامر Spec Kit وبنية مجلداتها تتغير بين الإصدارات؛ راجع README الرسمي للأداة قبل التنفيذ.

### ب) مع أي نموذج آخر (يدوياً)
1. ابدأ المحادثة بـ **System Prompt** من `06-ai-handoff.md §1`.
2. أرفق **حزمة السياق** الخاصة بالمرحلة (الجدول في `06 §2`) — لا ترفق كل الملفات دفعة واحدة.
3. أعطِ النموذج **مهمة واحدة أو مهمتين** من `04-tasks.md` بقالب `06 §3`.
4. اطلب منه أن يعيد: الملفات الكاملة + الأوامر التي شغّلها ونتائجها + الافتراضات.
5. شغّل **بوابة التحقق** (`06 §5`) قبل قبول العمل.
6. للمراجعة المتقاطعة: اعرض مخرجات نموذج على نموذج آخر بقالب `06 §4` (خصوصاً RLS والمال).

## 4. حلقة العمل لكل مهمة

```
اقرأ المهمة → اقرأ الأقسام المرتبطة من spec/data-model → اكتب الاختبار أولاً (خصوصاً RLS/المال)
→ نفّذ → typecheck + lint + test → راجع قائمة الدستور → التزم (commit) برسالة تحمل رقم المهمة
```

## 5. تعريف الإنجاز (Definition of Done) العام

- `pnpm typecheck && pnpm lint && pnpm test` ناجحة؛ ومهاجرات قاعدة البيانات تعمل على قاعدة نظيفة (`supabase db reset`).
- اختبارات pgTAP لأي جدول جديد (قبول/رفض لكل دور).
- لا نصوص ثابتة في المكوّنات (كلها في ملفات الترجمة) ولا خصائص CSS فيزيائية (`ml-`/`pl-`/`left`/`right`…).
- لا مفاتيح أو أسرار في الكود؛ `service_role` لا يظهر خارج `lib/supabase/admin.ts`.
- تحديث `docs/CHANGELOG.md` وذكر الافتراضات الجديدة.
